## F7 External Commissioning Gates

These five external gates are independent hard blockers for entry to `LIVE_1`. A gate may move to `PASSED` only when the recorded objective evidence directly demonstrates the stated pass condition. Secret values must never be stored in the tracker; evidence should use redacted permission exports, identifiers/fingerprints, signed approvals, or immutable evidence URIs/hashes.

| Gate ID | External gate | Status | Pass condition | Objective evidence required | Objective evidence recorded | Explicit blocker |
|---|---|---|---|---|---|---|
| F7.E1 | Trade-only credentials | BLOCKED | A dedicated production trading credential exists with only the minimum permissions required to read trading/account state and place/amend/cancel orders; it has no unrelated administrative or fund-movement privileges and is stored in approved secret management. | Redacted venue permission export/screenshot; credential inventory record with venue, account/environment, key ID/fingerprint, owner, creation/rotation dates and granted scopes; safe API permission test proving required trading operations are authorized. | NONE | No production venue/account credential has been supplied or verified. |
| F7.E2 | Withdrawals disabled | BLOCKED | The production trading credential cannot withdraw assets, manage withdrawal addresses, change bank/security settings, create privileged credentials, or transfer funds except any narrowly required transfer permission separately approved in writing. | Redacted venue permission export/screenshot showing withdrawal/transfer scopes disabled; safe negative API authorization test showing withdrawal/fund-movement action is denied; evidence URI/hash. | NONE | No venue credential exists from which withdrawal and transfer restrictions can be objectively verified. |
| F7.E3 | Operational approval | BLOCKED | An accountable human operator approves the exact system/adapter version, strategy scope, capital/risk limits, monitoring, reconciliation, kill-switch, incident response, credential-revocation, manual-flattening and restart procedures; a commissioning fault-recovery rehearsal is completed. | Signed or immutable operational commissioning record containing approver, timestamp, commit/version, limits and procedures; rehearsal evidence for normal → fault → HALT → reconciliation → human review → controlled restart. | NONE | No signed operational commissioning approval or rehearsal evidence has been recorded. |

| F7.E5 | Explicit live-capital authorization | BLOCKED | A named authorized human explicitly approves `LIVE_1` only for the specified venue/account, strategy IDs, system version, maximum capital, exposure, leverage, position, daily-loss and drawdown limits, with revocation conditions and an expiry/review point. | Signed or immutable live-capital authorization record containing approver, timestamp, system commit/version, venue/account identifier, strategies, approved limits, automatic-revocation conditions and expiry/review date. | NONE | No explicit human authorization to expose real capital has been granted. |

**F7 governing rule:** if any of `F7.E1`–`F7.E5` is not `PASSED`, the deployment stage remains `LIVE_0` and broker submission remains blocked. Passing all five external gates does not automatically authorize `LIVE_2`–`LIVE_4`; venue-specific `LIVE_1` commissioning evidence and subsequent scale evidence are still required.
